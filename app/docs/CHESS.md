# Local chess workflow

This opt-in example runs `examples/chess.cs`, not a simulated game. A coordinator Harness session delegates each turn via loopback A2A to two separate Harness worker processes. The chess rules validate moves and the coordinator response must match exactly one active player's completed A2A result. The UI polls snapshots of observed process events; they are not model progress estimates. The fixed inference endpoint is `http://127.0.0.1:8001/v1` and the model is `Qwen3.8-27B-oQ4e-mtp`; an available compatible local server and tool-capable model are required.

The server must opt in with `Chess:Enabled=true` and an absolute `Chess:ScriptPath` pointing to this checkout's `examples/chess.cs`. It needs a .NET SDK and restored script dependencies. Starting the game executes that local script and makes loopback inference and A2A requests; it is not a sandbox. Restrict the app server to loopback and use only a trusted checkout. Requests require a loopback peer; browser origins must be loopback, and mutation requests require a custom header. This is a local POC, not authentication or a multiuser security boundary. One game is allowed, at most 20 plies or five minutes. Stop/disconnect from the page does not automatically stop a game; use Stop, or wait for the deadline. Host shutdown also cancels. Failures and timeouts are reported without displaying process diagnostics.

The application registers the chess workflow and client and links to `/chess`; the game is disabled until configured as above. The session selector shows bounded, truncated coordinator prompts and responses and observed A2A player requests and responses, not internal model traces. The snapshot is unauthenticated and readable by other local processes; do not submit sensitive content. Supply configuration through the host's normal trusted local configuration, not committed credentials.

For the opt-in real integration test, from `app/` set `CHESS_TEST_SCRIPT` to the absolute chess script path and run `dotnet test --project tests/AGUIWebChat.Server.Tests --filter-method '*ChessWorkflowTests*'`. Without the variable the real-inference check returns without running; the other tests remain offline.


The opt-in real browser test runs from `app/` with `npx playwright test --config e2e/chess-tests/playwright.config.ts`. It starts isolated client and server processes on loopback ports 53992 and 53991, refuses to reuse existing servers, uses an in-memory application database, and performs real inference against the existing fixed local endpoint. That inference service must already be running; it is not started or stopped by the test. The test waits for two attributed player responses and a changed board. It is deliberately separate from the default stubbed E2E suite.
