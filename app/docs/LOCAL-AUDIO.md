# Local audio and speech

The Audio and speech page sends typed text to oMLX speech generation and WAV uploads to transcription. A transcript can be edited before generating speech, which is then playable and downloadable in the browser. These are complete, non-streaming requests. Enter a prompt or transcribe a WAV, then choose **Ask agent** to run the existing AG-UI chat agent in a fresh conversation. Review the response and choose **Use response for speech**, edit it if desired, then explicitly generate speech. This covers the agent-response step of all three `03-file-*` audio examples; the stdin example’s input is replaced by the prompt field. The agent uses the chat server’s default model and chat settings, which may route to an external provider; check that configuration before sending content.

Configure the server with `LocalAudio:Endpoint` (default `http://127.0.0.1:8001/v1/`), `LocalAudio:TranscriptionModel` (default `LFM3-Omni-2B-MLX-4bit`) and `LocalAudio:SpeechModel` (default `Ming-3.0-tts-tiny-4bit`). Models must already be available to oMLX. The endpoint accepts only a literal loopback IP over HTTP(S); proxies and redirects are disabled. It must be loopback **from the server process**, not the user's browser. The browser connects to the app server using its existing `AGUI_SERVER_URL` configuration and CORS policy.

Only WAV input is accepted, bounded to 10 MiB; generated WAV output is also bounded to 10 MiB. Text is limited to 4,000 characters. The app does not save uploads or results to files; downloading is an explicit browser action. The server sends uploaded audio and text to the local model service. Audio endpoints disable the app HTTP request-body logger, but other infrastructure or the model service may log content; do not submit secrets or sensitive material, and protect the app server/network. The endpoint has no dedicated authentication: use only in a trusted local deployment. File type checks recognize WAV headers, not the safety of audio content. There is no microphone capture or streaming.

The isolated browser pipeline test uses local mock audio and chat services: `npx playwright test --config=playwright.local-audio.config.ts --project=chromium`. It binds loopback ports 5198, 5298 and 5399.
